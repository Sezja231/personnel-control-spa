# Personnel Control SPA 3.1

Адаптивний демонстраційний SPA українською мовою: React + TypeScript + Vite + Tailwind CSS + Zustand. Локальні записи зберігаються у `localStorage`; опційний хмарний обмін реалізовано через Supabase Auth + PostgreSQL з перевіркою ролі адміністратора.

## Запуск у Windows 10/11

1. Встановіть Node.js LTS: https://nodejs.org/.
2. Розпакуйте архів у зручну папку.
3. Відкрийте папку проєкту `personnel-spa`.
4. Двічі клацніть `START.bat`. Перший запуск завантажить пакети через Інтернет.
5. Відкрийте `http://localhost:5173/`.

Для ручного запуску у терміналі:

```bash
npm install
npm run dev
```

Перевірка збірки:

```bash
npm run build
npm run preview
```

## Два способи доступу

### 1. Локально на комп'ютері

Дані цього браузера зберігаються в його `localStorage`. Це не серверна спільна база: інший браузер або пристрій матиме окреме локальне сховище.

### 2. Телефон у тій самій Wi-Fi мережі

Vite запускається з `--host 0.0.0.0`:

1. Запустіть `START.bat` на комп'ютері.
2. У CMD виконайте `ipconfig`, знайдіть IPv4-адресу активного адаптера.
3. На телефоні в тій самій Wi-Fi мережі відкрийте `http://IPv4-адреса:5173/`.
4. За потреби дозвольте Node.js доступ лише до приватної мережі у Windows Firewall.

Увага: такий доступ відкриває інтерфейс із телефона, але `localStorage` на телефоні окремий. Для спільних записів потрібен хмарний обмін або окремий внутрішній сервер/API.

### 3. Різні пристрої та різні мережі

Потрібні погоджений HTTPS-хостинг для фронтенду та Supabase-проєкт для бази. Це не налаштовується автоматично лише запуском `START.bat`.

1. Створіть Supabase-проєкт у https://supabase.com/.
2. У Supabase → SQL Editor виконайте весь файл `supabase/schema.sql`.
3. У Project Settings → API скопіюйте Project URL та publishable/anon key. Не використовуйте `service_role` ключ у браузері.
4. Скопіюйте `.env.example` як `.env.local` і заповніть `VITE_SUPABASE_URL` та `VITE_SUPABASE_ANON_KEY`.
5. Перезапустіть dev-сервер або зберіть production: `npm run build`.
6. У Supabase Auth створіть/запросіть користувача адміністратора. Вимкніть публічну реєстрацію, якщо вона не потрібна.
7. Призначте адміністратора SQL-командою від власника проєкту, підставивши його адресу:

```sql
insert into public.user_roles(user_id, role)
select id, 'admin' from auth.users where email = 'admin@example.com'
on conflict (user_id) do update set role = 'admin';
```

Для звичайного користувача (лише читання спільної хмарної бази) виконайте:

```sql
insert into public.user_roles(user_id, role)
select id, 'user' from auth.users where email = 'viewer@example.com'
on conflict (user_id) do update set role = 'user';
```

8. Адміністратор входить у SPA на кожному пристрої з тим самим обліковим записом. На першому пристрої натискає «Відправити локальні дані в хмару», на іншому — «Завантажити з хмари».

Хмарний обмін у цій версії ручний: це завантаження/відновлення цілого спільного знімка, а не автоматичне злиття одночасних змін. Перед перезаписом створіть резервну копію. Таблиця `personnel_shared_workspace` захищена RLS: `admin` може читати й записувати, `user` може лише читати спільний хмарний знімок. Роль `user` не блокує локальне редагування в браузері; вона обмежує запис у хмарну базу на рівні PostgreSQL.

## Можливості версії 3.1

- Огляд і окремі категорії: у строю, наряд, роботи, відпустка, лікарняний, відсутні.
- Особовий склад із випадаючими списками звань, посад, підрозділів та статусів.
- Призначення з вибором місця («Тернівка», «ЛСБ») і відповідального («Головний сержант», «Заступник командира»).
- Імпорт особового складу з Excel (`.xlsx`, `.xls`) або CSV. Підтримувані заголовки: `ПІБ`, `Звання`, `Посада`, `Підрозділ`, `Статус`.
- Призначення, календар.
- Щоденне зведення за вибрану дату.
- Місячний звіт за обраний місяць.
- Експорт звітів у `.xlsx`.
- Адміністративна сторінка з поточною роллю.
- Резервне копіювання та відновлення локальної бази у JSON.
- Локальне збереження Zustand/localStorage та опційний ручний хмарний обмін.

## Налаштування довідників

Переліки для випадаючих списків зберігаються в `src/data/options.ts`. Там можна додавати або змінювати звання, посади, підрозділи, місця та відповідальних. Старі значення вже створених карток не губляться: вони залишаються доступними під час редагування.

Новий порожній профіль не містить демонстраційних військовослужбовців. Імпорт Excel додає коректні рядки до наявного списку; рядки без ПІБ, посади або підрозділу пропускаються.

## Захист даних

Цей код є прототипом і не є сертифікованою системою захисту інформації. Не вводьте реальні персональні, медичні, службові, бойові або оперативно чутливі відомості. Для реального використання потрібні письмове погодження відповідальних за ІБ, оцінка ризиків, затверджена інфраструктура, HTTPS, керування доступом, аудит дій, резервне копіювання та перевірка відповідності політикам організації. Публічний хмарний сервіс може бути заборонений для таких даних.


## Розмежування прав (версія 3.2)

- Роль `admin`: може додавати, редагувати, видаляти особовий склад і призначення, імпортувати Excel та працювати з адмініструванням.
- Роль `user`: може переглядати дані та завантажувати спільний знімок із Supabase; кнопки редагування приховані.
- Якщо Supabase не налаштовано або користувач не увійшов, застосунок працює в режимі перегляду.
- Захист хмарних записів забезпечується RLS-політиками з `supabase/schema.sql`: читання дозволено учасникам, запис — лише `admin`. Не використовуйте ключ `service_role` у браузері.

Після оновлення перевірте, що в `public.user_roles` для вашого облікового запису встановлено `admin`, а для інших — `user`. Якщо SQL-схема вже була застосована, повторно виконайте `supabase/schema.sql` у Supabase SQL Editor, щоб оновити політики.
